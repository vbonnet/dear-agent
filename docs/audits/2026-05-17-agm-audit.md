# AGM Directory Documentation Audit — 2026-05-17

**Scope:** `agm/` only (docs, READMEs, ADRs, design specs, and code comments).
**Auditor:** parallel audit agent (agm/ partition).
**Method:** Full read of the ADR/mission cluster (`agm/docs/adr/ADR-020..025`,
`agm/docs/meta-orchestrator-mission.md`, RBAC code) plus four parallel
sub-audits covering `agm/docs/` (non-ADR), top-level `agm/*.md`, subdirectory
READMEs/ADRs, and Go/shell/YAML code comments.
**Disposition:** Report only. **No fixes applied** — remediation is owned by a
separate agent.

## Ground-truth definitions used for this audit

1. **VROOM is NOT an AGM concept.** VROOM is a higher-level governance /
   supervisory framework that *uses* AGM as a tool. AGM is a session manager.
   Any agm/ artifact that says VROOM is part of / owned by / implemented by /
   "AGM's" architecture is **wrong**.
2. **The old 5-role VROOM model is wrong and being replaced.** The deprecated
   model is **V**erifier / **R**equester / **O**rchestrator / **O**verseer /
   **M**eta-Orchestrator. Any artifact describing or depending on these five
   roles as *the* role model is a finding.
3. **DEAR = Define → Execute → Audit → Retro.** Any other expansion is wrong —
   in particular "Enforce" (for E), and "Resolve", "Resolve & Refine",
   "Remediate", "Reflect", "Refine" (for R).
4. **TypeScript:** the *only* legitimate TypeScript in the entire `agm/` tree is
   `agm/agm-plugin/channels/agm-bus/` (4 `.ts` files; that channel's own README
   documenting its TS is correct). The AGM core is Go. Any other doc claiming a
   TypeScript implementation/SDK of AGM is wrong.
