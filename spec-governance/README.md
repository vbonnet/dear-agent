# SPEC governance tooling

This directory owns two canonical skills and the deterministic tools that keep
their evidence and discovery surfaces honest:

- `skills/write-spec` authors one observable contract with explicit
  applicability and BDD consequences;
- `skills/audit-specs` performs a pinned, read-only ownership audit; and
- `cmd/sync-skill-projections` derives regular `.agents` entrypoints from the
  canonical skill metadata.

## Why generated regular projections

The authored workflow exists only under `spec-governance/skills`. Claude and Pi
load that canonical tree directly. Codex, AGY, and OpenCode use `.agents` as a
shared discovery surface, but not every active runtime discovers symlinked
entrypoints consistently. The committed `.agents` files are therefore regular,
minimal delegators generated from canonical metadata rather than handwritten
copies of either workflow.

`make lint-skills` checks generated bytes on every normal skill-validation
path. Write mode is restricted to the current registered linked Git worktree
and confines filesystem operations to that root. It creates only missing final
paths with exclusive, no-clobber creation; it never replaces or deletes an
existing entry. Stale or obsolete entries require human inspection of the
exact path and bytes followed by explicit removal. Complete-content publication
is intentionally not claimed to be atomic: an interrupted or failed write is
left in place for the same inspection instead of being cleaned up by pathname.

## Evidence and provenance

The process adapts Matt Pocock's evidence-first
[`improve-codebase-architecture`](https://github.com/mattpocock/skills/blob/main/skills/engineering/improve-codebase-architecture/SKILL.md)
and [HTML report](https://github.com/mattpocock/skills/blob/main/skills/engineering/improve-codebase-architecture/HTML-REPORT.md)
methods, his domain-modeling and codebase-design vocabulary, Anthropic's
skill-creator evaluation loop, EARS requirements, and Cucumber's
implementation-agnostic Gherkin guidance.

Temporal research, forward evaluations, the pinned corpus inventories, and the
rendered audit belong in `vbonnet/engram-research` under
`audits/dear-agent-spec-governance-2026-07-31`; they are intentionally not
living product documentation.

## Commands

```sh
make lint-skills
make sync-spec-skill-projections
go test ./spec-governance/...
```

Audit inventory and rendering emit artifact bytes only to standard output so
the shell's normal destination authorization remains visible and enforceable.
See the canonical skills and tool SPECs for the complete workflow and contract.
